## 各サービス構築・削除手順
### RDS構築
- RDS → データベース → データベースの作成
  - データベースの作成方法を選択　→　フル設定
  - エンジンのオプション
    - エンジンのタイプ　→　Aurora (MySQL Compatible)
    - エンジンバージョン　→　メジャーバージョンのデフォルト8.0
    - RDS延長サポートの有効化　→　オフ
  - テンプレート　→　開発/テスト
  - 設定　DBクラスター識別子　→　mytasknote-aurora-slsv2
  - 認証情報の設定
    - マスターユーザー名　→　admin
    - 認証情報管理　→　AWS Secrets Manager で管理 - 最も安全
    - 暗号化キーを選択　→　デフォルト
  - その他の認証情報の設定　→　すべてオフ
  - クラスターストレージ設定　設定オプション　→　Auroraスタンダード
  - インスタンスの設定
    - DBインスタンスクラス　インスタンスタイプ　→　Serverless v2
    - 容量の範囲　→　0.5～1
  - 可用性と耐久性　マルチAZ配置　→　レプリカを作成しない
  - 接続
    - コンピューティングリソース　→　EC2に接続しない
    - ネットワークタイプ　→　IPv4
    - VPC　→　デフォルト
    - DB　サブネットグループ　→　デフォルト
    - パブリックアクセス　→　なし
    - VPCセキュリティグループ　→　既存の選択
    - 既存のVPCセキュリティグループ　→　mytasknote-aurora-sg（デフォルトは外す）
    - アベイラビリティゾーン　→　指定なし
    - RDS Proxyを作成　→　オフ
    - 認証機関　→　デフォルト
    - RDS Data API　→　オフ
    - データベースポート　→　3306
  - リードレプリカへの書き込み転送　→　オフ
  - タグ　→　不要
  - モニタリング
    - データベースインサイト　→　スタンダード
    - performanceInsights　→　オフ
    - 拡張モニタリング　→　オフ
    - ログのエクスポート　→　オフ
  - 追加設定
    - 最初のデータベース名　→　mytasknote
    - DBクラスターのパラメータグループ、パラメータグループ　→　そのまま
    - フェイルオーバー優先順位　→　指定なし
    - バックアップ保持期間　→　1日間
    - バックアップウィンドウ　→　指定なし
    - バックアップタグ　→　すべてオフ
    - 暗号化キー　→　AWS所有KMSキー
    - バックトラック　→　オフ
    - メンテナンス　→　オフ
    - メンテナンスウィンドウ　→　指定なし
    - 削除保護の有効化　→　オフ

####RDS作成後、下記を控える
- エンドポイント（Writer endpoint）：DB識別子をクリック（インスタンスではないほう）　→　接続とセキュリティの接続手順にある「mysql -h ～ -P」の「～」の部分
- ポート：エンドポイントと同じで「-P～」P以降の部分
- DB名：エンドポイントと同じのコマンドの末尾「mytasknote」
- 
- Secrets Manager（Secret ARN）：DB識別子をクリック（インスタンスではないほう）　→　接続とセキュリティ　→　マスタークレデンシャルの ARN
- 
- 
- VPCセキュリティグループ：DB識別子をクリック（インスタンスのほう）　→　接続とセキュリティのSGのルール　→　mytasknote-aurora-sgになっていることを確認

###RDS、Secrets Managerの削除
####RDSの削除
1. インスタンスを削除（アクション　→　削除）
2. クラスターを削除：アクション　→　削除（最終スナップショットを作成：オフ、自動バックアップの保持：オフ）
3. スナップショット：RDSの左側（スナップショット、自動バックアップ）を確認して、残っていれば削除
####Secrets Managerの削除
1. Secrets Manager → シークレット一覧からシークレットを削除（復旧ウィンドウは最短を選択、7日？）
